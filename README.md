# DTF Prep

موقع ويب لتجهيز **تصاميم** طباعة DTF على التيشيرت. يستقبل صورة ومقاس الطباعة بالسنتيمتر، ويرجع ملف **PNG شفاف (RGBA)** بمقاس الطباعة الفعلي بدقة **300 DPI**.

> الموقع يشتغل على التصميم فقط: بدون White Base، بدون RIP، وبدون Gang Sheet.

## ماذا يفعل؟

1. **فحص الصورة**: يقرأ المقاس والدقة، ويعرض تنبيهاً إذا كانت الصورة ضعيفة جداً مقارنة بمقاس الطباعة (دقة فعلية أقل من 100 DPI).
2. **إزالة الخلفية** (تشغيل/إيقاف) بوضعين، وتُتجاوز تلقائياً إذا كانت الصورة شفافة أصلاً:
   - **تصميم بخلفية سادة (الافتراضي)**: للشعارات والنصوص والتصاميم بخلفية بلون واحد. يُكتشف لون الخلفية تلقائياً من حواف الصورة وزواياها، ويمكنك اختياره يدوياً بالضغط على الصورة. تُزال الخلفية بخوارزمية *flood fill* تبدأ من حواف الصورة فقط، فلا تُحذف العناصر الداخلية بنفس لون الخلفية (نجمة أو نص أبيض داخل شكل ملوّن، أو ثقب حرف O). سلايدر «حساسية اللون» يتحكم بمدى تقارب الألوان المحذوفة، وتُحسب شفافية الحافة بفصل لون الخلفية عن لون التصميم (وليس بقطع حاد) فلا تُؤكل التفاصيل الدقيقة. إن لم توجد خلفية سادة على الحواف تظهر رسالة تقترح اختيار اللون يدوياً أو وضع الذكاء الاصطناعي.
   - **صورة واقعية (ذكاء اصطناعي)**: للصور الواقعية والخلفيات المعقدة، بنموذج `isnet-general-use` عبر rembg.
3. **تنظيف الحواف**: إزالة الهالة البيضاء (defringe)، تصغير الحواف 0–3 بكسل، وتنعيم الحواف الخشنة مع حماية الخطوط الرفيعة.
4. **الشفافية الجزئية**: سلايدر «حدة الشفافية» يحدد عتبة؛ الأقل عتمة منها يصبح شفافاً والأعلى يصبح معتماً. وفيه خيار «بدون تغيير».
5. **التكبير** بـ Real-ESRGAN (على CPU) ثم ضبط المقاس بالضبط: `بكسل = (سم ÷ 2.54) × 300`.
6. **التصدير**: PNG بقناة ألفا مع DPI = 300 في الميتاداتا.

## الواجهة

شاشة واحدة بدون تنقل بين صفحات:

- **رفع الصورة** بالسحب والإفلات أو الاختيار؛ بعدها تختفي منطقة الرفع وتظهر الصورة مباشرة.
- **لوحتان: «قبل» و«بعد»** (فوق بعض على الجوال)، متزامنتان بالكامل: عجلة الماوس أو القرص بإصبعين للتكبير، والسحب للتحريك (من أي لوحة)، ونقرتان سريعتان أو زر «ملاءمة» للرجوع. ولوحة «بعد» خلفيتها شبكة شطرنج للشفافية.
- **معاينة مباشرة**: كل تحكم (وضع إزالة الخلفية، لون الخلفية، حساسية اللون، تصغير الحواف، حدة الشفافية) يحدّث لوحة «بعد» فوراً أثناء تحريك السلايدر، بدون زر «جهّز».
- **خلفية المعاينة**: أزرار ألوان التيشيرت (أبيض، أسود، أحمر، كحلي، رمادي، ولون مخصص) لترى الألوان التي تضيع أو تختفي.
- **اختيار لون الخلفية** بالضغط على صورة «قبل» (في وضع الخلفية السادة)، وزر «رجوع للتلقائي».
- **المقاس**: حقلا العرض والطول بالسنتيمتر مع «قفل النسبة» (مفعّل افتراضياً: تغيير أحدهما يحسب الآخر). عند رفع الصورة يُملأ العرض 30 سم تلقائياً. تحت الحقلين يظهر مباشرة: الدقة الفعلية عند هذا المقاس (DPI) وتنبيه أحمر إن كانت أقل من 100، وحجم الملف الناتج بالبكسل. ولو أُلغي القفل وأُدخلت نسبة مختلفة تظهر ملاحظة أن الصورة ستحافظ على نسبتها مع مساحة شفافة حولها.
- **الملف النهائي**: زر «حمّل الملف النهائي» يشغّل المعالجة الكاملة بدقة 300 DPI مع شريط تقدم، ثم ينزّل الملف. ولا يؤثر هذا على سرعة المعاينة. وزر «رجوع للافتراضي» يعيد قيم التحكمات.

### كيف تعمل المعاينة المباشرة؟

عند رفع الصورة تُنشأ **جلسة** على الخادم تحتفظ بالأصل وبنسخة مصغّرة (أطول ضلع 1000 بكسل). كل تعديل يُحسب على النسخة المصغّرة فقط، مع كاش لأثقل المراحل (قناع الذكاء الاصطناعي يُحسب مرة واحدة لكل صورة، ونتيجة إزالة الخلفية تُعاد فقط عند تغيير الوضع أو اللون أو الحساسية). قياسات من الاختبارات على CPU عادي: حوالي 50 مللي ثانية لتصغير الحواف وحدة الشفافية، وحوالي 200 مللي ثانية لتغيير حساسية اللون، وأول معاينة بالذكاء الاصطناعي بضع ثوانٍ ثم حوالي 30 مللي ثانية. هذه أزمنة المعالجة على الخادم؛ أضف إليها زمن الشبكة عند النشر البعيد.

**المعاينة تقريبية**: تُحسب على نسخة مصغّرة، فقد يختلف الناتج النهائي بفروق طفيفة عند الحواف. ويُحوَّل «تصغير الحواف» بالنسبة إلى دقة المعالجة الكاملة (مثلاً 1 بكسل من صورة 3000 بكسل يعادل 0.33 بكسل في المعاينة). المرجع النهائي هو الملف المحمَّل.


### ملاحظات مهمة عن السلوك

- **نسبة الأبعاد**: إذا اختلفت نسبة الصورة عن المقاس المُدخل، لا تُشوَّه الصورة؛ تُحفظ النسبة وتُضاف مساحة شفافة حولها ليكون الملف بالمقاس المطلوب بالبكسل بالضبط (وتظهر ملاحظة بذلك).
- **الصورة الأكبر من المطلوب** تُصغَّر إلى دقة الطباعة (300 DPI) في البداية.
- **التكبير الذكي**: يُستخدم Real-ESRGAN للصور حتى 2 ميجابكسل (على CPU يأخذ من ثوانٍ إلى دقائق حسب الحجم). الصور الأكبر تُكبَّر بـ Lanczos. والتكبير الأكبر من ×4 يتم بمرحلة ثانية إن كان الحجم المتوسط معقولاً، وإلا يكمل Lanczos.
- **القطع الحاد للشفافية** يُطبَّق على الألفا بعد التكبير حتى تخرج الحافة ناعمة المحيط بدون تسنن، لكن العتبة التي تختارها هي نفسها.
- «تصغير الحواف» يُحسب ببكسلات الصورة وقت المعالجة (قبل التكبير).
- وضع الذكاء الاصطناعي يركّز على العنصر الأبرز؛ قد يحذف عناصر بيضاء أو نصوصاً منفصلة عن الشكل الرئيسي. للتصاميم ذات الخلفية السادة استخدم وضع «تصميم بخلفية سادة»، وإلا فأوقف «إزالة الخلفية» وارفع تصميماً شفافاً، أو جرّب `REMBG_MODEL=birefnet-general`.
- في وضع الخلفية السادة: إذا كان التصميم نفسه يلمس حافة الصورة بلون قريب من الخلفية فقد يُحذف الجزء الملامس؛ اترك هامشاً حول التصميم أو خفّض «حساسية اللون».

## التشغيل المحلي

المتطلبات: Python 3.10 – 3.12 (يعمل أيضاً على 3.13) ومساحة ~600 ميجابايت للنماذج.

```bash
git clone <رابط-المستودع> dtf-prep
cd dtf-prep

python -m venv .venv
source .venv/bin/activate          # على ويندوز: .venv\Scripts\activate

pip install -r requirements.txt

# اختياري: تنزيل النماذج مسبقاً (وإلا تُنزَّل عند أول تشغيل)
python scripts/download_models.py

uvicorn app.main:app --host 127.0.0.1 --port 8000
```

افتح <http://127.0.0.1:8000>.

تشغيل الاختبارات:

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

اختبار اختياري للواجهة في متصفح حقيقي (يحتاج Playwright وخادماً شغّالاً):

```bash
pip install playwright && playwright install chromium
uvicorn app.main:app --port 8000 &
DTF_URL=http://127.0.0.1:8000 python tests/ui_smoke.py
```

## Docker

```bash
docker build -t dtf-prep .
docker run --rm -p 7860:7860 dtf-prep
```

ثم افتح <http://localhost:7860>. النماذج تُنزَّل أثناء البناء فتكون جاهزة فوراً.

## النشر على Hugging Face Spaces

1. أنشئ Space جديداً واختر **SDK: Docker** (الحزمة المجانية CPU Basic تكفي).
2. ارفع ملفات المشروع إلى مستودع الـ Space (أو اربطه بمستودع GitHub).
3. أضف هذا الرأس في **أول** ملف `README.md` داخل مستودع الـ Space:

   ```yaml
   ---
   title: DTF Prep
   emoji: 🎽
   colorFrom: teal
   colorTo: gray
   sdk: docker
   app_port: 7860
   pinned: false
   ---
   ```

4. انتظر اكتمال البناء. المنفذ الافتراضي في `Dockerfile` هو `7860` وهو ما يتوقعه Spaces.

## النشر على Railway

1. ارفع المشروع إلى GitHub، ثم في Railway: **New Project → Deploy from GitHub repo**.
2. سيكتشف Railway ملف `Dockerfile` تلقائياً ويبني منه. ولا تحتاج متغيرات بيئة (Railway يمرّر `PORT` وهو مدعوم).
3. من **Settings → Networking** اضغط **Generate Domain** للحصول على رابط عام.
4. يُنصح بذاكرة **2 جيجابايت على الأقل**؛ المقاسات الكبيرة (مثل 60×60 سم) تحتاج أكثر. وللتأكد من الجاهزية استخدم المسار `/api/health`.

## الإعدادات (متغيرات بيئة اختيارية)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `DTF_MAX_UPLOAD_MB` | `20` | أقصى حجم للملف المرفوع |
| `DTF_MAX_INPUT_MP` | `60` | أقصى حجم للصورة المرفوعة بالميجابكسل |
| `DTF_MAX_SIDE_CM` | `120` | أقصى طول لأي ضلع في مقاس الطباعة |
| `DTF_MAX_OUTPUT_MP` | `80` | أقصى حجم للملف الناتج بالميجابكسل (يعادل ~ 58×58 سم) |
| `DTF_ESRGAN_MAX_INPUT_MP` | `2` | أكبر صورة تُكبَّر بالذكاء الاصطناعي |
| `REMBG_MODEL` | `isnet-general-use` | نموذج إزالة الخلفية (`birefnet-general` أدق وأبطأ وأثقل) |
| `DTF_JOB_TTL_SECONDS` | `1800` | مدة بقاء الملفات المؤقتة قبل حذفها تلقائياً |
| `DTF_PRELOAD` | `1` | تسخين النماذج عند بدء التشغيل |
| `DTF_LIVE_PREVIEW_SIDE` | `1000` | أطول ضلع للنسخة المصغّرة المستخدمة في المعاينة المباشرة |
| `DTF_SESSION_TTL_SECONDS` | `3600` | مدة بقاء جلسة الصورة بدون استخدام قبل حذفها |
| `DTF_MAX_SESSIONS` | `12` | أقصى عدد جلسات نشطة (الأقدم يُحذف) |

## واجهة الـ API

| المسار | الوصف |
|---|---|
| `POST /api/sessions` | رفع الصورة وإنشاء جلسة معاينة (يرجع `session_id` ومقاس الصورة ولون الخلفية المكتشف) |
| `POST /api/sessions/{id}/preview` | معاينة سريعة: PNG شفاف على النسخة المصغّرة (نفس خيارات المعالجة). ترجع الترويسات `X-Bg-Color` و`X-Bg-Manual` |
| `DELETE /api/sessions/{id}` | حذف الجلسة |
| `POST /api/process` | المعالجة الكاملة؛ تقبل `file` أو `session_id` (بدون إعادة رفع) |
| `GET /api/jobs/{id}` | حالة المعالجة والتقدم |
| `GET /api/jobs/{id}/result` | تنزيل الملف النهائي |

## تفاصيل تقنية

- **Real-ESRGAN بدون PyTorch**: يُستخدم النموذج الرسمي `realesr-general-x4v3` (≈5 ميجابايت). تُقرأ أوزانه `.pth` وتُحوَّل عند أول تشغيل إلى رسم ONNX وتُشغَّل عبر onnxruntime على CPU، فلا حاجة لـ PyTorch وتبقى الصورة خفيفة.
- **الذاكرة**: التكبير على أجزاء 192×192 مع هامش، ويُتخطى الأجزاء الشفافة بالكامل.
- **الخصوصية**: الملف المرفوع للمعالجة النهائية يُحذف بعد المعالجة مباشرة، وملفات النتائج تُحذف تلقائياً بعد 30 دقيقة. وجلسة المعاينة (الأصل والنسخة المصغّرة) تُحذف عند مغادرة الصفحة أو تغيير الصورة، أو تلقائياً بعد ساعة بدون استخدام.
- المعالجة تتم بالتتابع (مهمة واحدة في كل مرة) لحماية الذاكرة؛ ويرى المستخدم رقم دوره إن كان هناك انتظار.
