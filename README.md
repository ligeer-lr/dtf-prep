# DTF Prep

موقع ويب لتجهيز **تصاميم** طباعة DTF على التيشيرت. يستقبل صورة ومقاس الطباعة بالسنتيمتر، ويرجع ملف **PNG شفاف (RGBA)** بمقاس الطباعة الفعلي بدقة **300 DPI**.

> الموقع يشتغل على التصميم فقط: بدون White Base، بدون RIP، وبدون Gang Sheet.

## ماذا يفعل؟

1. **فحص الصورة**: يقرأ المقاس والدقة، ويعرض تنبيهاً إذا كانت الصورة ضعيفة جداً مقارنة بمقاس الطباعة (دقة فعلية أقل من 100 DPI).
2. **إزالة الخلفية** (تشغيل/إيقاف) بنموذج `isnet-general-use` عبر rembg. تُتجاوز تلقائياً إذا كانت الصورة شفافة أصلاً.
3. **تنظيف الحواف**: إزالة الهالة البيضاء (defringe)، تصغير الحواف 0–3 بكسل، وتنعيم الحواف الخشنة مع حماية الخطوط الرفيعة.
4. **الشفافية الجزئية**: سلايدر «حدة الشفافية» يحدد عتبة؛ الأقل عتمة منها يصبح شفافاً والأعلى يصبح معتماً. وفيه خيار «بدون تغيير».
5. **التكبير** بـ Real-ESRGAN (على CPU) ثم ضبط المقاس بالضبط: `بكسل = (سم ÷ 2.54) × 300`.
6. **التصدير**: PNG بقناة ألفا مع DPI = 300 في الميتاداتا.

وفي الواجهة: معاينة قبل/بعد، ومعاينة على ألوان التيشيرت (أبيض، أسود، أحمر، كحلي، رمادي، ولون مخصص) لترى الألوان التي تضيع أو تختفي.

### ملاحظات مهمة عن السلوك

- **نسبة الأبعاد**: إذا اختلفت نسبة الصورة عن المقاس المُدخل، لا تُشوَّه الصورة؛ تُحفظ النسبة وتُضاف مساحة شفافة حولها ليكون الملف بالمقاس المطلوب بالبكسل بالضبط (وتظهر ملاحظة بذلك).
- **الصورة الأكبر من المطلوب** تُصغَّر إلى دقة الطباعة (300 DPI) في البداية.
- **التكبير الذكي**: يُستخدم Real-ESRGAN للصور حتى 2 ميجابكسل (على CPU يأخذ من ثوانٍ إلى دقائق حسب الحجم). الصور الأكبر تُكبَّر بـ Lanczos. والتكبير الأكبر من ×4 يتم بمرحلة ثانية إن كان الحجم المتوسط معقولاً، وإلا يكمل Lanczos.
- **القطع الحاد للشفافية** يُطبَّق على الألفا بعد التكبير حتى تخرج الحافة ناعمة المحيط بدون تسنن، لكن العتبة التي تختارها هي نفسها.
- «تصغير الحواف» يُحسب ببكسلات الصورة وقت المعالجة (قبل التكبير).
- نموذج إزالة الخلفية العام يركّز على العنصر الأبرز؛ قد يحذف عناصر بيضاء أو نصوصاً منفصلة عن الشكل الرئيسي. إن حدث ذلك: أوقف «إزالة الخلفية» وارفع الصورة بخلفية شفافة جاهزة، أو استخدم نموذجاً أدق (`REMBG_MODEL=birefnet-general`).

## التشغيل المحلي

المتطلبات: Python 3.10 – 3.12 (يعمل أيضاً على 3.13) ومساحة ~600 ميجابايت للنماذج.

```bash
git clone <رابط-المستودع> dtf-prep
cd dtf-prep

python -m venv .venv
source .venv/bin/activate          # على ويندوز: .venv\Scripts\activate

pip install -r requirements.txt

# اختياري: تنزيل النماذج مسبقاً (وإلا تُنزَّل عند أول تشغيل)
python scripts/download_models.py

uvicorn app.main:app --host 127.0.0.1 --port 8000
```

افتح <http://127.0.0.1:8000>.

تشغيل الاختبارات:

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

## Docker

```bash
docker build -t dtf-prep .
docker run --rm -p 7860:7860 dtf-prep
```

ثم افتح <http://localhost:7860>. النماذج تُنزَّل أثناء البناء فتكون جاهزة فوراً.

## النشر على Hugging Face Spaces

1. أنشئ Space جديداً واختر **SDK: Docker** (الحزمة المجانية CPU Basic تكفي).
2. ارفع ملفات المشروع إلى مستودع الـ Space (أو اربطه بمستودع GitHub).
3. أضف هذا الرأس في **أول** ملف `README.md` داخل مستودع الـ Space:

   ```yaml
   ---
   title: DTF Prep
   emoji: 🎽
   colorFrom: teal
   colorTo: gray
   sdk: docker
   app_port: 7860
   pinned: false
   ---
   ```

4. انتظر اكتمال البناء. المنفذ الافتراضي في `Dockerfile` هو `7860` وهو ما يتوقعه Spaces.

## النشر على Railway

1. ارفع المشروع إلى GitHub، ثم في Railway: **New Project → Deploy from GitHub repo**.
2. سيكتشف Railway ملف `Dockerfile` تلقائياً ويبني منه. ولا تحتاج متغيرات بيئة (Railway يمرّر `PORT` وهو مدعوم).
3. من **Settings → Networking** اضغط **Generate Domain** للحصول على رابط عام.
4. يُنصح بذاكرة **2 جيجابايت على الأقل**؛ المقاسات الكبيرة (مثل 60×60 سم) تحتاج أكثر. وللتأكد من الجاهزية استخدم المسار `/api/health`.

## الإعدادات (متغيرات بيئة اختيارية)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `DTF_MAX_UPLOAD_MB` | `20` | أقصى حجم للملف المرفوع |
| `DTF_MAX_INPUT_MP` | `60` | أقصى حجم للصورة المرفوعة بالميجابكسل |
| `DTF_MAX_SIDE_CM` | `120` | أقصى طول لأي ضلع في مقاس الطباعة |
| `DTF_MAX_OUTPUT_MP` | `80` | أقصى حجم للملف الناتج بالميجابكسل (يعادل ~ 58×58 سم) |
| `DTF_ESRGAN_MAX_INPUT_MP` | `2` | أكبر صورة تُكبَّر بالذكاء الاصطناعي |
| `REMBG_MODEL` | `isnet-general-use` | نموذج إزالة الخلفية (`birefnet-general` أدق وأبطأ وأثقل) |
| `DTF_JOB_TTL_SECONDS` | `1800` | مدة بقاء الملفات المؤقتة قبل حذفها تلقائياً |
| `DTF_PRELOAD` | `1` | تسخين النماذج عند بدء التشغيل |

## تفاصيل تقنية

- **Real-ESRGAN بدون PyTorch**: يُستخدم النموذج الرسمي `realesr-general-x4v3` (≈5 ميجابايت). تُقرأ أوزانه `.pth` وتُحوَّل عند أول تشغيل إلى رسم ONNX وتُشغَّل عبر onnxruntime على CPU، فلا حاجة لـ PyTorch وتبقى الصورة خفيفة.
- **الذاكرة**: التكبير على أجزاء 192×192 مع هامش، ويُتخطى الأجزاء الشفافة بالكامل.
- **الخصوصية**: الملف المرفوع يُحذف بعد المعالجة مباشرة، وبقية الملفات المؤقتة تُحذف تلقائياً بعد 30 دقيقة أو عند طلب «معالجة صورة جديدة».
- المعالجة تتم بالتتابع (مهمة واحدة في كل مرة) لحماية الذاكرة؛ ويرى المستخدم رقم دوره إن كان هناك انتظار.
